# Season Anime Picker — MVP実装タスク

## 1. 進め方

- マイルストーンは `M0 → M1 → M2 → M3 → M4 → M5 → M6` の順に進める。
- 各マイルストーンは記載された完了条件を満たしてから次へ進む。
- 実装中に仕様判断が必要になった場合は、まず `requirements.md` と `architecture.md` を正として扱う。
- MVP対象外の機能は、後続タスクとしても同時実装しない。
- テスト可能なドメイン処理はUIより先に作成する。

## 2. マイルストーン一覧

| ID | マイルストーン | 依存 | 成果 |
| --- | --- | --- | --- |
| M0 | プロジェクト基盤 | なし | 起動・検証可能な空アプリ |
| M1 | 型とドメインロジック | M0 | API契約、純粋関数、保存スキーマ |
| M2 | AniList Route Handler | M1 | シーズン検索API |
| M3 | 検索とカード一覧 | M1、M2 | 検索結果を表示できる画面 |
| M4 | フィルターと並び替え | M1、M3 | クライアント内の絞り込み・ソート |
| M5 | 見る候補 | M1、M3 | localStorage永続化付き候補リスト |
| M6 | レスポンシブ・アクセシビリティ・最終QA | M2〜M5 | MVP完成判定 |

- [ ] ステータスの日本語ラベル変換を実装する。
- [ ] 話数、評価、人気度の表示フォーマッターを実装する。
- [ ] 最低評価、最大話数、ジャンル、TVのみのフィルター関数を実装する。

- [ ] 欠損値を末尾へ置き、同値時に日本語タイトル順とする。

### テスト

- [ ] タイトルの段階的フォールバックと全欠損を検証する。
- [ ] 評価・話数が不明な作品のフィルター規則を検証する。
- [ ] 4フィルターの単独・複合条件を検証する。
- [ ] 3種類の並び替え、欠損値、同順位を検証する。
- [ ] `TV` と `TV_SHORT` が区別される。
- [ ] ジャンル候補が重複なく安定した順序になる。
- [ ] 同じAniList IDを重複追加できない。
- [ ] 不正JSON、未知バージョン、不正な項目が空配列へ復旧する。

### 完了条件

UIやネットワークに依存しないドメイン処理が完成し、単体テストがすべて成功する。

## M2 — AniList Route Handler

### 目的

AniListへのアクセスをサーバー側に閉じ込め、検証済みのシーズン全件を安定したアプリ用APIとして返す。

### タスク

- [ ] `GET /api/anime` のRoute Handlerを作成する。
- [ ] `year` の必須・整数・範囲検証を実装する。
- [ ] `season` の列挙値検証を実装する。
- [ ] AniList GraphQLクエリを定義する。
- [ ] `perPage: 50` でのページ取得処理を実装する。
- [ ] `hasNextPage = false` まで最大5ページを取得する。
- [ ] ページ途中の失敗時に部分結果を返さない。
- [ ] `isAdult: false` をクエリに指定する。
- [ ] 正規化時にも `isAdult === true` を除外する。
- [ ] AniListレスポンスをZodで検証する。
- [ ] `AnimeSummary` へ正規化する。
- [ ] AniList呼び出しへ10秒のタイムアウトを設定する。
- [ ] Next.js Cache Componentsを有効にする。
- [ ] `anilistSeason` キャッシュプロファイルを定義する。
- [ ] 年・季節を引数に持つキャッシュ関数へAniList取得処理を配置する。
- [ ] `fetchedAt` をISO 8601で付与する。
- [ ] 400、429、502、504のレスポンスをAPI契約どおりに変換する。
- [ ] 429では `Retry-After` と `retryAfterSeconds` を可能な限り引き継ぐ。
- [ ] 上流本文やスタックトレースをクライアントへ返さない。

### テスト

- [ ] 正常な1ページ結果を200で返す。
- [ ] 複数ページを順に取得して1つの配列へ統合する。
- [ ] 成人向け作品が最終結果に含まれない。
- [ ] タイトルと各enumがDTOへ正規化される。
- [ ] 検索結果0件を200と空配列で返す。
- [ ] 年・季節の欠落と不正値を400へ変換する。
- [ ] AniList 429を429へ変換し、待機秒数を引き継ぐ。
- [ ] 上流HTTPエラーとGraphQLエラーを502へ変換する。
- [ ] Zod検証失敗を502へ変換する。
- [ ] 最大ページ超過を502として部分結果を返さない。
- [ ] 10秒タイムアウトを504へ変換する。

### 完了条件

AniListをモックしたRoute Handlerテストがすべて成功し、クライアントがAniList固有のレスポンスを扱わずに済む。

- [ ] 追加時に現在の年・季節をスナップショットへ含める。
- [ ] AniList IDによる重複防止を実装する。

- [ ] 破損値・未知バージョンから安全に復旧する。

### テスト

- [ ] 候補追加後にカードと候補欄の状態が同期する。
- [ ] 同じ作品を重複追加できない。

- [ ] localStorage例外時も検索結果を閲覧できる。

### 完了条件

## 3. 実装しない事項

次の項目はMVP完了条件に含めず、各マイルストーンへ追加しない。

- 認証、AniListアカウント同期
- 作品詳細、配信先、キャスト、スタッフ
- 複数候補リスト、メモ、個人評価、進捗
- 共有、通知、エクスポート
- サーバーDB、クラウド同期
- URL状態、無限スクロール、タブ間同期
- ダークモード、多言語、成人向け切替
- 分析、広告、課金
