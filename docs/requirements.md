# Season Anime Picker — MVP要件定義

本書は、Season Anime Pickerの実装・検証を担当する開発者向けに、MVP（Minimum Viable Product：必要最小限の機能を備えた製品）の範囲、期待する振る舞い、受け入れ条件を定義する。

## 1. 文書の目的

本書はMVPの機能要件、画面状態、対象外事項、受け入れ条件を定義する。実装時の判断を揃え、MVPの範囲を明確にする。

仕様は本書を正とする。実装方法とテスト方針は[アーキテクチャ](architecture.md)、実装順序と完了状況は[実装タスク](tasks.md)を参照する。

## 2. プロダクト概要

この節では、アプリの目的、想定ユーザー、MVPの成功条件を示す。

### 2.1 目的

ユーザーが年と季節を指定し、対象クールのアニメを比較・絞り込みして、自分の「見る候補」リストを作成できるようにする。

### 2.2 想定ユーザー

想定ユーザーは次のとおりとする：

- 放送クールごとに視聴作品を選びたいアニメ視聴者
- 評価、人気度、話数、ジャンルをまとめて比較したいユーザー
- アカウント登録なしで手軽に候補を保存したいユーザー

### 2.3 MVPの成功条件

MVPは次の条件を満たす：

- 年と季節を指定して対象クールの作品一覧を取得できる
- 取得済み一覧を評価、話数、ジャンル、放送形式で絞り込める
- 評価、人気度、話数で並び替えられる
- 候補の追加・削除ができ、ブラウザを再読み込みしても保持される
- デスクトップと幅375pxのスマートフォンで主要操作を完了できる
- ローディング、0件、通信失敗、レート制限をユーザーが区別できる

## 3. 用語

本書では次の用語を使用する：

| 用語 | 定義 |
| --- | --- |
| シーズン | 年と `WINTER`、`SPRING`、`SUMMER`、`FALL` の組み合わせ |
| クール | シーズンに対応する3か月の放送期間 |
| 作品 | AniList APIのアニメメディア1件 |
| 検索結果 | 指定したシーズンについてAPIから取得した、成人向けを除く全作品 |
| 表示結果 | 検索結果に現在のフィルターと並び替えを適用した作品 |
| 見る候補 | ユーザーが候補として保存した作品。シーズンをまたいで共有する |
| 評価 | AniListの `averageScore`。既知の場合は0〜100の数値、不明の場合は `null` |
| 人気度 | AniListの `popularity`。作品をリストに登録しているユーザー数。不明の場合は `null` |
| Route Handler | Next.jsでサーバー側のAPIリクエストを処理する仕組み |
| localStorage | ブラウザ内にデータを保存する仕組み。見る候補の永続化に使用する |
| Skeleton | データの読み込み中に、表示領域の形を示す仮のUI |
| SSR | Server-Side Rendering。サーバー側で画面を生成する処理 |
| DTO | Data Transfer Object。アプリ内で共有するデータ形式 |

## 4. 機能要件

機能要件をFR-01〜FR-08で識別する。各要件はMVPの必須動作とする。

### FR-01 年・季節の選択

検索条件の入力と実行は次の規則に従う：

- トップ画面に年と季節の入力欄を表示する。
- 年は1940年から現在年の翌年までを許可する。
- 初期値はユーザーが画面を開いた時点の現在年・現在季節とする。
- 季節の内部値は `WINTER | SPRING | SUMMER | FALL` のいずれかとする。
- ユーザーが検索ボタンを押したときだけ検索を実行する。

月から季節への対応は次のとおりとする：

| 月 | 季節の内部値 |
| --- | --- |
| 1〜3月 | `WINTER` |
| 4〜6月 | `SPRING` |
| 7〜9月 | `SUMMER` |
| 10〜12月 | `FALL` |

### FR-02 シーズン検索

検索リクエストの処理は次の規則に従う：

- 指定された年と季節をNext.js Route Handlerへ送信する。
- Route HandlerはAniList APIから対象シーズンの全ページを取得する。
- `isAdult = true` の作品は常に除外する。
- 新しい検索を開始した場合、進行中の直前リクエストを中断する。
- 検索開始時には以前のエラーを消し、ローディング状態を表示する。
- 自動再試行は行わない。失敗時には、失敗した検索に送信した年と季節で手動再試行できる。

### FR-03 アニメカード

各カードには次の7項目を表示する：

- タイトル
- カバー画像
- 話数
- 評価スコア
- 人気度
- ジャンル
- 放送ステータス

各カードには「見る候補」への追加状態と操作ボタンも表示する。

表示規則は次のとおりとする：

- タイトルは `native → romaji → english` の優先順で最初に存在する値を使用する。
- すべてのタイトルが欠ける場合は「タイトル未登録」と表示する。
- 話数が不明な場合は「話数未定」と表示する。
- 評価が不明な場合は「未評価」と表示する。
- 人気度は桁区切り付きの整数で表示する。
- 人気度が不明な場合は「不明」と表示する。
- カバー画像がない、または読み込みに失敗した場合は共通プレースホルダーを表示する。
- 放送ステータスは日本語ラベルへ変換する。

放送ステータスと表示ラベルの対応は次のとおりとする：

| AniListステータス | 表示ラベル |
| --- | --- |
| `RELEASING` | 放送中 |
| `FINISHED` | 放送終了 |
| `NOT_YET_RELEASED` | 放送前 |
| `CANCELLED` | 放送中止 |
| `HIATUS` | 休止中 |
| その他・不明 | 不明 |

### FR-04 フィルター

フィルターはAPIの再取得を行わず、取得済みの検索結果に対して即時に適用する。

各フィルターの初期値と動作は次のとおりとする：

| フィルター | 初期値 | 動作 |
| --- | --- | --- |
| 評価スコアの下限 | 指定なし | 指定値以上の作品を残す。評価不明は、下限指定時のみ除外する |
| 最大話数 | 指定なし | 指定値以下の作品を残す。話数不明は、最大話数指定時のみ除外する |
| ジャンル | すべて | 単一選択とし、選択したジャンルを含む作品を残す。「すべて」の場合はジャンルで絞り込まない |
| TVアニメのみ | ON | `format` が `TV` の作品だけを残す。`TV_SHORT` は含めない |

選択肢とフィルター適用は次の規則に従う：

- ジャンル選択肢は検索結果に含まれるジャンルの重複を除き、表示名順に生成する。
- 新しいシーズン検索が成功した場合、フィルターは初期値へ戻す。
- 複数のフィルターが指定された場合はAND条件で適用する。
- フィルター後に0件となった場合は、条件を緩めるよう案内する。

### FR-05 並び替え

並び替えは次の規則に従う：

- 初期値は評価順とする。
- 評価順は `averageScore` の降順とする。
- 人気順は `popularity` の降順とする。
- 話数順は `episodes` の昇順とする。
- 並び替え対象の値が不明な作品は末尾へ置く。
- 並び替え対象の値が同値、または両方とも不明な場合は、日本語ロケールのタイトル昇順とする。
- 並び替え変更時にAPIを再取得しない。

### FR-06 見る候補

候補の追加・削除と保持は次の規則に従う：

- 各カードから作品を「見る候補」へ追加できる。
- 候補はAniList IDを一意キーとし、同じ作品を重複追加しない。
- 追加済み作品のボタンは追加済み状態を明示し、再追加できないようにする。
- 候補セクションから作品を1件ずつ削除できる。
- 候補は検索中のシーズンに限定せず、全シーズンで共有する。
- 候補には追加時点の表示用データを保存し、バックグラウンド同期は行わない。
- 候補が0件の場合は、追加方法を説明する空状態を表示する。

### FR-07 localStorage永続化

候補の保存と復元は次の規則に従う：

- localStorageキーは `season-anime-picker:candidates:v1` とする。
- 保存データはJSONとし、型で表した構造は `{ version: 1, items: CandidateAnime[] }` とする。`CandidateAnime` の定義は[候補のデータ型](../src/features/season-picker/types.ts)を参照する。
- SSR中はlocalStorageへアクセスしない。
- クライアント側の読み込みが完了するまで、候補欄に専用Skeletonを表示する。
- JSON破損、期待しない型、未知のバージョンを検出した場合は、例外で画面を停止させず空リストへ戻す。
- タブ間のリアルタイム同期は行わない。

### FR-08 ローディングとエラー

検索の進行状況とエラーは次の規則に従って表示する：

- 初回検索前は、年と季節を選ぶよう案内する。
- 検索中はカード形状のSkeletonを表示し、検索ボタンを連打できないようにする。
- 検索結果が0件の場合は専用の空状態を表示する。
- 一般的な通信エラーでは、説明と再試行ボタンを表示する。
- AniListのレート制限では、通常の通信エラーと区別し、再試行可能になるまでの秒数が取得できる場合は表示する。
- タイムアウトでは、時間を置いて再試行するよう案内する。
- エラーメッセージに内部例外、スタックトレース、上流レスポンス本文をそのまま表示しない。

## 5. レスポンシブUI要件

画面幅に応じた配置と操作の要件を定義する。

### デスクトップ

デスクトップでは次の配置とする：

- 検索、フィルター、並び替えを上部に配置する。
- メイン領域をカードグリッドと「見る候補」サイドレールに分ける。
- 候補レールは画面内に追従してよいが、ページ全体のスクロールを妨げない。

### スマートフォン

スマートフォンでは次の配置と操作を満たす：

- 幅375pxで横スクロールを発生させない。
- 検索・フィルターを縦方向に並べる。
- アニメカードは1列表示とする。
- 候補セクションはカード一覧の後に独立セクションとして表示する。
- タップ対象は十分な大きさを確保し、主要操作をキーボードでも実行可能にする。

## 6. 非機能要件

品質と実装上の制約をNFR-01〜NFR-04で識別する。「利用してよい」と記載した手段は任意とする。

### NFR-01 アクセシビリティ

入力・表示・操作は次の要件を満たす：

- 入力、トグル、ボタンには関連付けられたラベルを設定する。
- フォーカス状態を視覚的に判別できるようにする。
- カバー画像には作品タイトルを含む代替テキストを設定する。
- 色だけで放送状態、選択状態、エラーを伝えない。
- ローディングや検索結果件数の変更を支援技術が認識できるようにする。

### NFR-02 性能

通信と描画は次の要件を満たす：

- フィルターと並び替えはクライアント側で完結し、追加のAPIリクエストを発生させない。
- シーズン結果はサーバー側でキャッシュし、同一条件によるAniListへの重複アクセスを抑える。
- 長いカード一覧では、画面外要素の描画コストを抑えるCSSを利用してよい。

### NFR-03 セキュリティとプライバシー

データの取得・保存・公開は次の要件を満たす：

- AniListの公開データ取得に認証情報を使用しない。
- 候補情報はユーザーのブラウザ内だけに保存し、サーバーへ送信しない。
- Route Handlerは許可された年と季節だけを受け付ける。
- 上流APIのエラー詳細をクライアントへ直接露出しない。

### NFR-04 保守性

データ境界と処理の分離は次の要件を満たす：

- AniList固有レスポンスとアプリ内DTOを分離する。
- フィルター、並び替え、候補保存処理はUIから分離した純粋関数または専用フックとして実装する。
- 公開API、localStorage形式、エラーコードは型とテストで固定する。

## 7. 画面状態

検索、画像、候補欄の状態ごとの表示と操作を次の表に示す。画像と候補欄の状態は、検索の状態とは別に扱う：

| 状態 | 表示 | 操作 |
| --- | --- | --- |
| 初期 | 検索案内、空の結果領域 | 年・季節選択、検索 |
| ローディング | Skeleton、検索中表示 | 検索の再実行を抑止 |
| 成功 | 件数、フィルター、カード一覧 | 絞り込み、並び替え、候補追加 |
| 検索結果0件 | シーズンに作品がない旨 | 条件変更、再検索 |
| フィルター結果0件 | 条件を緩める案内 | フィルター変更 |
| 通信エラー | 安全なエラー説明 | 手動再試行 |
| レート制限（HTTP 429） | 待機案内、取得できる場合は待機秒数 | 時間経過後に手動再試行 |
| タイムアウト | 時間を置いて再試行する案内 | 手動再試行 |
| 画像欠損 | 共通プレースホルダー | 他のカード操作は継続 |
| 候補0件 | 候補追加方法の案内 | カードから追加 |
| 候補読込中 | 候補用Skeleton | 読み込み完了まで待機 |

## 8. MVP対象外

次の機能はMVPに含めない：

- ユーザー登録、ログイン、認証
- AniListアカウントとのリスト同期
- 作品詳細ページ、キャスト、スタッフ、配信先情報
- 複数の候補リスト
- メモ、個人評価、視聴進捗
- 候補リストの共有・エクスポート
- 通知、放送リマインダー
- サーバーDB、クラウド同期
- URLへの検索条件保存
- クライアント側ページネーション、無限スクロール
- タブ間のリアルタイム同期
- ダークモード
- 多言語対応
- 成人向け作品の表示切替
- アナリティクス、広告、課金

## 9. 受け入れ条件

MVPの受け入れ判定では、次の条件をすべて確認する。AC-01〜AC-11を各条件の識別子とする：

- **AC-01**: 有効な年と4季節の任意の組み合わせで検索できる。[FR-01](#fr-01-年季節の選択)に従う。
- **AC-02**: Route Handler経由で対象シーズンの非成人向け作品を全ページ取得できる。[FR-02](#fr-02-シーズン検索)に従う。
- **AC-03**: カードにタイトル、カバー画像、話数、評価スコア、人気度、ジャンル、放送ステータスと候補操作を表示する。欠損値の表示は[FR-03](#fr-03-アニメカード)に従い、レイアウトが破綻しない。
- **AC-04**: 評価スコアの下限、最大話数、ジャンル、TVアニメのみの各フィルターを単独・複合で適用できる。[FR-04](#fr-04-フィルター)に従う。
- **AC-05**: 評価順、人気順、話数順が欠損値と同順位を含めて[FR-05](#fr-05-並び替え)どおりに動作する。
- **AC-06**: 候補を重複なく追加・削除できる。[FR-06](#fr-06-見る候補)に従う。
- **AC-07**: 再読み込み後および別シーズン検索後も候補が保持される。[FR-07](#fr-07-localstorage永続化)に従い、保存データの破損、型の不一致、未知のバージョンでも画面が停止せず空リストへ戻る。
- **AC-08**: 初期、ローディング、検索結果0件、フィルター結果0件、通信エラー、レート制限（HTTP 429）、タイムアウトを区別して表示できる。[画面状態](#7-画面状態)に従う。
- **AC-09**: エラー状態から、失敗した検索に送信した年と季節で手動再試行できる。[FR-02](#fr-02-シーズン検索)と[FR-08](#fr-08-ローディングとエラー)に従う。
- **AC-10**: デスクトップと幅375pxで横スクロールがなく、検索から候補削除まで完了できる。[レスポンシブUI要件](#5-レスポンシブui要件)に従う。
- **AC-11**: 主要操作をキーボードで実行でき、ラベル、フォーカス、画像代替テキストを確認できる。[NFR-01](#nfr-01-アクセシビリティ)に従い、色に依存しない状態表示と、支援技術によるローディング・件数変更の認識を確認できる。

## 10. 確定済み前提

MVPの範囲を決める前提は次のとおりとする。各機能の詳細は[機能要件](#4-機能要件)を参照する：

- プロジェクトは空の状態から新規に開始したものとする。
- 候補リストは全シーズンで共有する。
- 作品タイトルは原題を優先する。
- 成人向け作品は常に除外する。
- 「TVアニメのみ」はAniListの `format` が `TV` の作品を対象とする。
- 候補データは追加時のスナップショットとし、自動更新しない。
