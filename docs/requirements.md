# Season Anime Picker — MVP要件定義

## 1. 文書の目的

本書は「Season Anime Picker」MVPの機能要件、画面状態、対象外事項、受け入れ条件を定義する。実装時に判断が分かれないこと、およびMVPの範囲が不用意に広がらないことを目的とする。

## 2. プロダクト概要

### 2.1 目的

ユーザーが年と季節を指定し、対象クールのアニメを比較・絞り込みして、自分の「見る候補」リストを作成できるようにする。

### 2.2 想定ユーザー

- 放送クールごとに視聴作品を選びたいアニメ視聴者
- 評価、人気度、話数、ジャンルをまとめて比較したいユーザー
- アカウント登録なしで手軽に候補を保存したいユーザー

### 2.3 MVPの成功条件

- 年と季節を指定して対象クールの作品一覧を取得できる
- 取得済み一覧を評価、話数、ジャンル、放送形式で絞り込める
- 評価、人気度、話数で並び替えられる
- 候補の追加・削除ができ、ブラウザを再読み込みしても保持される
- デスクトップと幅375pxのスマートフォンで主要操作を完了できる
- ローディング、0件、通信失敗、レート制限をユーザーが区別できる

## 3. 用語

| 用語 | 定義 |
| --- | --- |
| シーズン | 年と `WINTER`、`SPRING`、`SUMMER`、`FALL` の組み合わせ |
| 作品 | AniList APIのアニメメディア1件 |
| 検索結果 | 指定したシーズンについてAPIから取得した、成人向けを除く全作品 |
| 表示結果 | 検索結果に現在のフィルターと並び替えを適用した作品 |
| 見る候補 | ユーザーが候補として保存した作品。シーズンをまたいで共有する |
| 評価 | AniListの `averageScore`。0〜100の数値 |
| 人気度 | AniListの `popularity`。作品をリストに登録しているユーザー数 |

## 4. 機能要件

### FR-01 年・季節の選択

- トップ画面に年と季節の入力欄を表示する。
- 年は1940年から現在年の翌年までを許可する。
- 初期値はユーザーが画面を開いた時点の現在年・現在季節とする。
- 月から季節への対応は次のとおりとする。
  - 1〜3月: `WINTER`
  - 4〜6月: `SPRING`
  - 7〜9月: `SUMMER`
  - 10〜12月: `FALL`
- 季節の内部値は `WINTER | SPRING | SUMMER | FALL` のいずれかとする。
- ユーザーが検索ボタンを押したときだけ検索を実行する。

### FR-02 シーズン検索

- 指定された年と季節をNext.js Route Handlerへ送信する。
- Route HandlerはAniList APIから対象シーズンの全ページを取得する。
- `isAdult = true` の作品は常に除外する。
- 新しい検索を開始した場合、進行中の直前リクエストを中断する。
- 検索開始時には以前のエラーを消し、ローディング状態を表示する。
- 自動再試行は行わない。失敗時には同じ条件で手動再試行できる。

### FR-03 アニメカード

各カードには以下を表示する。

- タイトル
- カバー画像
- 話数
- 評価スコア
- 人気度
- ジャンル
- 放送ステータス
- 「見る候補」への追加状態と操作ボタン

表示規則は次のとおりとする。

- タイトルは `native → romaji → english` の優先順で最初に存在する値を使用する。
- すべてのタイトルが欠ける場合は「タイトル未登録」と表示する。
- 話数が不明な場合は「話数未定」と表示する。
- 評価が不明な場合は「未評価」と表示する。
- 人気度は桁区切り付きの整数で表示する。
- カバー画像がない、または読み込みに失敗した場合は共通プレースホルダーを表示する。
- 放送ステータスは日本語ラベルへ変換する。

| AniListステータス | 表示ラベル |
| --- | --- |
| `RELEASING` | 放送中 |
| `FINISHED` | 放送終了 |
| `NOT_YET_RELEASED` | 放送前 |
| `CANCELLED` | 放送中止 |
| `HIATUS` | 休止中 |
| その他・不明 | 不明 |

### FR-04 フィルター

フィルターはAPIの再取得を行わず、取得済みの検索結果に対して即時に適用する。

| フィルター | 初期値 | 動作 |
| --- | --- | --- |
| 評価スコアの下限 | 指定なし | 指定値以上の作品を残す。評価不明は、下限指定時のみ除外する |
| 最大話数 | 指定なし | 指定値以下の作品を残す。話数不明は、最大話数指定時のみ除外する |
| ジャンル | すべて | 選択ジャンルを1つ以上含む作品を残す |
| TVアニメのみ | ON | `format === TV` の作品だけを残す。`TV_SHORT` は含めない |

- ジャンル選択肢は検索結果に含まれるジャンルの重複を除き、表示名順に生成する。
- 新しいシーズン検索が成功した場合、フィルターは初期値へ戻す。
- 複数のフィルターが指定された場合はAND条件で適用する。
- フィルター後に0件となった場合は、条件を緩めるよう案内する。

### FR-05 並び替え

- 初期値は評価順とする。
- 評価順は `averageScore` の降順とする。
- 人気順は `popularity` の降順とする。
- 話数順は `episodes` の昇順とする。
- 並び替え対象の値が不明な作品は末尾へ置く。
- 主キーが同値または不明同士の場合は、日本語ロケールのタイトル昇順で安定化する。
- 並び替え変更時にAPIを再取得しない。

### FR-06 見る候補

- 各カードから作品を「見る候補」へ追加できる。
- 候補はAniList IDを一意キーとし、同じ作品を重複追加しない。
- 追加済み作品のボタンは追加済み状態を明示し、再追加できないようにする。
- 候補セクションから作品を1件ずつ削除できる。
- 候補は検索中のシーズンに限定せず、全シーズンで共有する。
- 候補には追加時点の表示用データを保存し、バックグラウンド同期は行わない。
- 候補が0件の場合は、追加方法を説明する空状態を表示する。

### FR-07 localStorage永続化

- localStorageキーは `season-anime-picker:candidates:v1` とする。
- 保存形式は `{ version: 1, items: CandidateAnime[] }` とする。
- SSR中はlocalStorageへアクセスしない。
- クライアント側の読み込みが完了するまで、候補欄に専用Skeletonを表示する。
- JSON破損、期待しない型、未知のバージョンを検出した場合は、例外で画面を停止させず空リストへ戻す。
- タブ間のリアルタイム同期は行わない。

### FR-08 ローディングとエラー

- 初回検索前は、年と季節を選ぶよう案内する。
- 検索中はカード形状のSkeletonを表示し、検索ボタンを連打できないようにする。
- 検索結果が0件の場合は専用の空状態を表示する。
- 一般的な通信エラーでは、説明と再試行ボタンを表示する。
- AniListのレート制限では、通常の通信エラーと区別し、再試行可能になるまでの秒数が取得できる場合は表示する。
- タイムアウトでは、時間を置いて再試行するよう案内する。
- エラーメッセージに内部例外、スタックトレース、上流レスポンス本文をそのまま表示しない。

## 5. レスポンシブUI要件

### デスクトップ

- 検索、フィルター、並び替えを上部に配置する。
- メイン領域をカードグリッドと「見る候補」サイドレールに分ける。
- 候補レールは画面内に追従してよいが、ページ全体のスクロールを妨げない。

### スマートフォン

- 幅375pxで横スクロールを発生させない。
- 検索・フィルターを縦方向に並べる。
- アニメカードは1列表示とする。
- 候補セクションはカード一覧の後に独立セクションとして表示する。
- タップ対象は十分な大きさを確保し、主要操作をキーボードでも実行可能にする。

## 6. 非機能要件

### NFR-01 アクセシビリティ

- 入力、トグル、ボタンには関連付けられたラベルを設定する。
- フォーカス状態を視覚的に判別できるようにする。
- カバー画像には作品タイトルを含む代替テキストを設定する。
- 色だけで放送状態、選択状態、エラーを伝えない。
- ローディングや検索結果件数の変更を支援技術が認識できるようにする。

### NFR-02 性能

- フィルターと並び替えはクライアント側で完結し、追加のAPIリクエストを発生させない。
- シーズン結果はサーバー側でキャッシュし、同一条件によるAniListへの重複アクセスを抑える。
- 長いカード一覧では、画面外要素の描画コストを抑えるCSSを利用してよい。

### NFR-03 セキュリティとプライバシー

- AniListの公開データ取得に認証情報を使用しない。
- 候補情報はユーザーのブラウザ内だけに保存し、サーバーへ送信しない。
- Route Handlerは許可された年と季節だけを受け付ける。
- 上流APIのエラー詳細をクライアントへ直接露出しない。

### NFR-04 保守性

- AniList固有レスポンスとアプリ内DTOを分離する。
- フィルター、並び替え、候補保存処理はUIから分離した純粋関数または専用フックとして実装する。
- 公開API、localStorage形式、エラーコードは型とテストで固定する。

## 7. 画面状態

| 状態 | 表示 | 操作 |
| --- | --- | --- |
| 初期 | 検索案内、空の結果領域 | 年・季節選択、検索 |
| ローディング | Skeleton、検索中表示 | 検索の再実行を抑止 |
| 成功 | 件数、フィルター、カード一覧 | 絞り込み、並び替え、候補追加 |
| 検索結果0件 | シーズンに作品がない旨 | 条件変更、再検索 |
| フィルター結果0件 | 条件を緩める案内 | フィルター変更 |
| 通信エラー | 安全なエラー説明 | 手動再試行 |
| レート制限 | 待機案内、待機秒数 | 時間経過後に再試行 |
| 画像欠損 | 共通プレースホルダー | 他のカード操作は継続 |
| 候補0件 | 候補追加方法の案内 | カードから追加 |
| 候補読込中 | 候補用Skeleton | 読み込み完了まで待機 |

## 8. MVP対象外

- ユーザー登録、ログイン、認証
- AniListアカウントとのリスト同期
- 作品詳細ページ、キャスト、スタッフ、配信先情報
- 複数の候補リスト
- メモ、個人評価、視聴進捗
- 候補リストの共有・エクスポート
- 通知、放送リマインダー
- サーバーDB、クラウド同期
- URLへの検索条件保存
- クライアント側ページネーション、無限スクロール
- タブ間のリアルタイム同期
- ダークモード
- 多言語対応
- 成人向け作品の表示切替
- アナリティクス、広告、課金

## 9. 受け入れ条件

1. 有効な年と4季節の任意の組み合わせで検索できる。
2. Route Handler経由で対象シーズンの非成人向け作品を全ページ取得できる。
3. カードに必須7項目と候補操作が表示され、欠損値でもレイアウトが破綻しない。
4. 最低評価、最大話数、ジャンル、TVのみの各フィルターを単独・複合で適用できる。
5. 評価順、人気順、話数順が欠損値と同順位を含めて定義どおりに動作する。
6. 候補を重複なく追加・削除できる。
7. リロード後および別シーズン検索後も候補が保持される。
8. 初期、ローディング、0件、一般エラー、429、タイムアウトを区別して表示できる。
9. エラー状態から同じ検索条件で手動再試行できる。
10. デスクトップと幅375pxで横溢れがなく、検索から候補削除まで完了できる。
11. 主要操作をキーボードで実行でき、ラベル、フォーカス、画像代替テキストが設定されている。

## 10. 確定済み前提

- 新規の空プロジェクトとして開始する。
- 候補リストは全シーズンで共有する。
- 作品タイトルは原題を優先する。
- 成人向け作品は常に除外する。
- `TVアニメのみ` はAniListの `format === TV` とする。
- 候補データは追加時のスナップショットとし、自動更新しない。
